# Chapter 44.3 — UI (Widgets)

> **Core idea:** The UI system is **Immediate-Mode** (rebuilt every frame, no
> persistent widget tree) and renders directly via OpenGL/OpenGL ES — no external dependency.
> The layout model is based on a **grid system** with f32 size values (0.0–1.0),
> rowspan/colspan, and arbitrary nesting.
> All sizes are normalized — not a single hardcoded pixel value in the layout.
> The grid scales automatically to any resolution and platform.

---

## Architecture

```
┌─────────────────────────────────────────────────────────────┐
│  Widget API       ui.label / ui.button / ui.progress_bar    │
│                   ui.begin_grid / ui.begin_cell              │
├─────────────────────────────────────────────────────────────┤
│  Layout Engine    Grid → compute cell rects                 │
│                   Rowspan/Colspan → merge rects              │
│                   f32 sizes → pixel rects (with DPI scale)  │
├─────────────────────────────────────────────────────────────┤
│  2D Batch Renderer  build draw list (quads, text quads)     │
│                     ui.end() → single flush to OpenGL       │
├─────────────────────────────────────────────────────────────┤
│  Text Renderer    stb_truetype (single-header)              │
│                   Font atlas (bitmap) on GPU texture        │
└─────────────────────────────────────────────────────────────┘
```

`ui.begin()` starts a new UI frame and resets the draw list.
All widget calls between `begin` and `end` build the draw list.
`ui.end()` computes layouts, performs hit tests, and flushes everything to OpenGL.

## 2. Frame Lifecycle

| Call | Description |
|------|-------------|
| `ui.init()` | Optional: create the UI state explicitly (e.g. before loading fonts). Every other `ui.*` call initializes it on first use, so it may be omitted. |

## 3. Grid Layout

### 3.1 Size Units

Column and row sizes are passed as **`buffer<f32>`**.
Each value represents the share of the available space:

| Value | Meaning |
|-------|---------|
| `0.0 < x < 1.0` | Fixed share: `0.2` = 20% of available space |
| `1.0` | **Flexible**: takes the remaining space after subtracting all fixed shares; multiple `1.0` entries split the remainder equally |

**Examples:**

```
[0.2, 1.0, 0.2]   →  20%  |  60% (remainder)  |  20%
[0.15, 1.0, 0.15] →  15%  |  70% (remainder)  |  15%
[1.0, 1.0, 1.0]   →  33%  |  33%              |  33%  (three equally wide columns)
[0.3, 0.7]        →  30%  |  70%
[1.0]             →  100% (single column)
```

### 3.2 Grid Commands

| Call | Description |
|------|-------------|
| `ui.begin_grid(cols: buffer<f32>, rows: buffer<f32>)` | Span a grid |
| `ui.end_grid()` | Close the grid |
| `ui.set_gap(h: f32, v: f32)` | Gap between cells in logical pixels; must be set before `begin_grid` |

### 3.3 Cells

```aiml
- call: [ui.begin_cell, col, row, colspan, rowspan]
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `col` | `i32` | Column index (0-based) |
| `row` | `i32` | Row index (0-based) |
| `colspan` | `i32` | Number of columns spanned (`1` = no spanning) |
| `rowspan` | `i32` | Number of rows spanned (`1` = no spanning) |

```aiml
- call: [ui.end_cell]
```

All four parameters must always be specified — AIML has no default parameters.
A cell with `colspan=2, rowspan=2` occupies the four cells
`(col,row)`, `(col+1,row)`, `(col,row+1)`, `(col+1,row+1)` —
identical to HTML `<td colspan="2" rowspan="2">`.
Writing into occupied cells is not allowed.

### 3.4 Content Alignment

Set before `begin_cell`, applies only to the next cell:

```aiml
- call: [ui.set_align, h, v]
```

`h`: `"left"` / `"center"` / `"right"`
`v`: `"top"` / `"middle"` / `"bottom"`

### 3.5 Nesting

A sub-grid can be opened inside a cell.
The cell size becomes the new 100% basis of the sub-grid.

```aiml
- call: [ui.begin_cell, 1, 1, 1, 1]
  - call: [ui.begin_grid, [0.5, 0.5], [0.5, 0.5]]
  - call: [ui.begin_cell, 0, 0, 1, 1]
  - call: [ui.button, "A"]
  - call: [ui.end_cell]
  - call: [ui.begin_cell, 1, 0, 1, 1]
  - call: [ui.button, "B"]
  - call: [ui.end_cell]
  - call: [ui.end_grid]
- call: [ui.end_cell]
```

### 3.6 Scrollable Cells

Set before `begin_cell`, applies only to the next cell (the setting is consumed):

```aiml
- call: [ui.set_scroll, "y"]
- call: [ui.begin_cell, 0, 0, 1, 1]
```

| Call | Description |
|------|-------------|
| `ui.set_scroll(axis: string)` | Make the next cell scrollable. `"y"`, `"x"` or `"xy"`; `""` cancels |

- The cell keeps its rectangle; its content is clipped to it and shifted by the scroll offset.
- A scrollbar is reserved per axis (10 logical pixels of the cell's width resp. height) and is
  drawn only while the content is larger than the cell. Its thumb can be dragged.
- The mouse wheel over the cell scrolls by 40 logical pixels per tick, unless an open dropdown
  covers the cursor (§4.2). The wheel is **not** consumed towards the application:
  `input.mouse_scroll` still reports it, so a caller that also zooms on the wheel has to ask
  where the cursor is.
- The offset is kept between frames, keyed by grid depth and the cell's row/column, and clamped
  to the content size measured in the previous frame.

**Offen:** the content *width* is not measured (it is taken to be the cell width), so `"x"`
reserves the bar but never scrolls. Only `"y"` is useful today.

## 4. Widgets

All widget functions accept an **optional last argument** of type
`ui_XXX_style` (→ §5.2). If omitted, the global style stack applies.

### 4.1 Text

| Call | Return | Description |
|------|--------|-------------|
| `ui.label(text: string [, style: ui_label_style])` | — | Text element in current style color |
| `ui.label_colored(text: string, color: i32 [, style: ui_label_style])` | — | Text with explicit RGBA color |
| `ui.text_input(id: string, buffer: string [, style: ui_label_style])` | `string` | Single-line input field |
| `ui.password_input(id: string, buffer: string [, style: ui_label_style])` | `string` | Single-line input that draws one `•` per UTF-8 character instead of the text and never offers it to the clipboard; otherwise exactly `text_input` — the returned buffer is the real text (F44-3-20) |
| `ui.password_mask(text: string)` | `string` | The caption `password_input` draws for `text`: one `•` (U+2022) per UTF-8 character (F44-3-21) |
| `ui.text_area(id: string, buffer: string [, style: ui_label_style])` | `string` | Multi-line input field |
| `ui.measure_text(text: string [, style: ui_label_style])` | `f32` | Width of `text` in the font `ui.label` would use |
| `ui.text_height([style: ui_label_style])` | `f32` | Line height of that same font |

#### Measuring and drawing must agree

Both measuring calls resolve the font **exactly** as `ui.label` does: an optional preset is
pushed onto the style stack for the duration of the call and popped again. So
`ui.measure_text(t, st)` and `ui.label(t, st)` cannot disagree, and passing the same preset
to both is the whole discipline — measuring in one style and drawing in another is the one
way to get a wrong answer out of these calls.

- They need `ui.init` and a font (`ui.set_default_font`, or one in the passed preset).
  Without either, both return `0.0` rather than guessing a size.
- They are independent of the frame: no `ui.begin` is required, and they work outside any
  cell. Measuring is not laying out — neither call advances the cell cursor, emits a vertex
  or pushes a scissor. This is deliberate, so a layout can be *computed* before the frame
  it is drawn in.
- Both results are in **window pixels** — the same space as widget rects, as
  `input.mouse_pos()` and as the `ui.draw_*` coordinates (§4.6). That is the space a box
  around the text has to be sized in, so no conversion sits between measuring and using.
- See spec/44_6 §5i for `engine.text_width` / `engine.text_height`, the separate pair for
  the prefab scene font. The two fonts are independent.
- `ui.measure_text` is the sum of the glyph advances for **one line**: no trailing bearing,
  no wrapping. A string containing `\n` is *not* split — measure the lines yourself and
  take the maximum. (Said explicitly because the opposite guess is reasonable and fails
  quietly, returning the width of every line laid end to end.)
- Codepoints outside `32..255` are skipped, the same ones `push_text` skips when drawing
  (§6). A measured string and a drawn string therefore stay the same width.

### 4.2 Interaction

| Call | Return | Description |
|------|--------|-------------|
| `ui.button(label: string [, style: ui_button_style])` | `i32` | `1` if clicked in this frame, else `0` |
| `ui.button_icon(label: string, icon: gl_texture)` | `i32` | Button with icon to the left of the text; `1` if clicked |
| `ui.checkbox(id: string, value: i32 [, style: ui_button_style])` | `i32` | Returns the new state (`0`/`1`) |
| `ui.toggle(id: string, value: i32 [, style: ui_button_style])` | `i32` | Toggle switch; returns the new state (`0`/`1`) |
| `ui.radio(id: string, option: i32, current: i32 [, style: ui_button_style])` | `i32` | Returns selected option |
| `ui.spinbox(id: string, options: list<string>, current: i32 [, style: ui_button_style])` | `i32` | Dropdown over `options`; returns the selected index |

**`ui.spinbox`** — the header shows `options[current]` and a `v`, and is as wide as the cell.
A click opens the list below the header (above it when it would leave the window), a click on a
row selects it and closes the list, a click anywhere else closes it without a change. The list
shows at most 12 rows (fewer in a short window); beyond that the wheel scrolls it and a
scrollbar appears. The popup is drawn after every other widget, so it covers what lies under
it, and it is **not** clipped by a scrollable cell it sits in. While it is open it also **takes
the input over its area**: a widget underneath is neither hovered nor clickable, and the wheel
there scrolls the list instead of the cell around it. The shield is the rect of the previous
frame, so a UI that stops calling the spinbox while its list is open keeps that area blocked
for one frame. `current` is clamped into
`[0, len-1]`; an empty list gives an empty header. At most one dropdown is open at a time
(the open one holds the UI focus); the `id` carries that focus and must therefore be stable
across frames.

### 4.6 Free Drawing

| Call | Arguments | Description |
|------|-----------|-------------|
| `ui.draw_line` | `x0, y0, x1, y1: f32, width: f32, color: i32` | Straight line between two points |
| `ui.draw_polyline` | `pts: buffer<f32>, width: f32, color: i32` | Connected line through `[x0,y0, x1,y1, ...]` |
| `ui.draw_text` | `x, y: f32, text: string, color: i32 [, style: ui_label_style]` | One line of text with its **top-left** at `x,y` |
| `ui.draw_rect` | `x, y, w, h: f32, color: i32` | A filled rectangle at that position |
| `ui.draw_image` | `x, y, w, h: f32, tex: gl_texture` | A texture into that rect |

These are the only UI calls that draw at a position the caller chose rather than one the
grid chose. They exist for surfaces the grid cannot describe — ink, a graph edge, a
free-form canvas.

**Coordinates are window pixels**, absolute and not cell-relative: the same space as
widget rects, as `input.mouse_pos()` (spec/44_0 §2.3) and as `ui.measure_text` (§4.1). A
stroke drawn under the cursor therefore needs no conversion — which is the point, since
every caller of these two is drawing something the pointer traced. `width`, by contrast, is
in **logical pixels** and is DPI-scaled like `padding` or `font_size`, so a 2 px line stays
2 px thick on a HiDPI screen.

They draw; they do not lay out, so neither call advances the cell cursor or reserves space.

**Clipping.** Called inside a cell, the drawing is clipped to that cell's padded rect —
which is what makes a scrollable drawing surface possible (§3.6). Called outside any cell,
it is clipped only by the window. The clip is pushed and cleared around the drawing, in
the same per-widget way every other widget handles its scissor; nothing leaks to the next
call.

**Width** is centred on the line (±`width`/2). `width <= 0` draws nothing, and so does a
zero-length line — a degenerate input is never a dot. `color` is `0xRRGGBBAA` and is multiplied by the current style opacity, like every
other widget colour.

**`ui.draw_polyline`** reads `pts` as consecutive `x,y` pairs. Fewer than two points
(fewer than 4 floats) draws nothing; a trailing odd float is ignored rather than read as a
point with a garbage `y`.

**Joints are not mitred** — each segment is an independent quad. At 1–2 px this is
invisible; at large widths a corner shows a notch. That is the accepted trade for keeping
this a batch primitive with no joint geometry and no per-corner state: a caller who needs
mitres draws them. Stated because the alternative, discovering it at width 10, looks like a
bug.

**`ui.draw_text`** is the canvas counterpart of `ui.label` (§4.1): a label lays itself out
in a cell, this one draws where it is told. `x,y` is the **top-left of the line box**, the
same corner every other `draw_*` coordinate means, so a caller that measured with
`ui.measure_text`/`ui.text_height` (§4.1) can place a box around the text and the text
inside it from the same two numbers.

It applies **no width limit of its own**: clipping is the cell's job (above). A soft
per-glyph limit here would silently shorten a label the caller had already sized, and a
label one glyph short is not a visible failure.

**`ui.draw_rect`** is to `ui.rect` (§4.4) what `draw_text` is to `label`. Its `w`/`h` are
window pixels and are **not** DPI-scaled, unlike a line's `width`: a stroke width describes
how thick a pen is and should follow the screen, while a rectangle's size describes
geometry and must not. Filling a rect with a thick `draw_line` instead would inherit the
line's scaling and come out wrong on a HiDPI screen — which is why this call exists rather
than that trick.

**`ui.draw_image`** is to `ui.image_sized` (§4.4) what `draw_text` is to `label`: that one
fills the cell it sits in, this one draws into the rect it is given. No SDF rounding — a
picture is not a rounded rect, and the rounding fields would cut its corners. A `w` or `h`
of `0` or less draws nothing.

All five calls append to the same vertex batch as every other UI draw and are ordered with
it: a line issued after a `ui.rect` covers it. No separate GL state, no flush, no second
pipeline.

## 5. Style System

### 5.1 Global Style Stack

Styles are managed as a push/pop stack — `push` temporarily overrides properties,
`pop` restores the previous state.

```aiml
- decl: [s, ui_style]
- set: [s.font_size,     24.0]
- set: [s.color,         0xFFFFFFFF]
- set: [s.bg_color,      0x1A1A2EFF]
- set: [s.border_color,  0x4444AAFF]
- set: [s.border_width,  1.0]
- set: [s.corner_radius, 6.0]
- set: [s.padding_x,     0.05]   # 5% gap from cell edge
- call: [ui.push_style, s]
- call: [ui.label, "Styled Text"]
- call: [ui.pop_style]
```

### `ui_style` — Members

| Member | Type | Default | Description |
|--------|------|---------|-------------|
| `font` | `ui_font` | Default font | Active font |
| `font_size` | `f32` | `16.0` | Font size in logical pixels |
| `color` | `i32` | `0xEEEEEEFF` | Foreground color (text, icons) as RGBA |
| `bg_color` | `i32` | `0x2A2A3EFF` | Background color |
| `hover_color` | `i32` | `0x3D3D6AFF` | Background on hover |
| `active_color` | `i32` | `0x5566CCFF` | Background on click/active |
| `border_color` | `i32` | `0x6666AAFF` | Border color |
| `border_width` | `f32` | `1.0` | Border width in logical pixels |
| `corner_radius` | `f32` | `3.0` | Corner radius in logical pixels |
| `padding_h` | `f32` | `8.0` | Horizontal **inner** padding (widget content ↔ widget edge) |
| `padding_v` | `f32` | `4.0` | Vertical **inner** padding |
| `opacity` | `f32` | `1.0` | Transparency (0.0 = invisible, 1.0 = fully opaque) |
| `padding_x` | `f32` | `0.0` | Horizontal **outer** gap from cell edge as fraction of cell width (0.0–0.5); `0.05` = 5% left and right each |
| `padding_y` | `f32` | `0.0` | Vertical **outer** gap from cell edge as fraction of cell height |
| `size_w` | `f32` | `-1.0` | Absolute widget width in logical pixels; `-1.0` = fill available width after `padding_x` |
| `size_h` | `f32` | `-1.0` | Absolute widget height in logical pixels; `-1.0` = auto (determined by content) |

#### Outer Padding and Absolute Size — Semantics

```
┌─────────────────────── Cell Rect ──────────────────────────┐
│◄── padding_x × cell_w ──►│         │◄── padding_x × cell_w ──►│
│                           ┌─────────┐                          │
│  ▲ padding_y × cell_h    │ Widget  │                          │
│                           │  Rect   │                          │
│  ▼                        └─────────┘                          │
└────────────────────────────────────────────────────────────────┘
```

- `padding_x = 0.05` → the widget uses `cell_w × 0.90` as available width,
  horizontally centered in the cell space.
- If `size_w > 0`: widget width = `min(size_w × dpi, available_width)`.
  If `size_w × dpi` is **larger** than the available width (incl. outer padding),
  the widget is **clipped** at the cell edge (GL Scissor Test).
- `size_w` and `size_h` work **independently** — only one dimension may be
  set to an absolute value.

Global theme (base of the style stack):

```aiml
- call: [ui.set_default_style, s]
```

### 5.2 Widget Style Presets

Style preset objects encapsulate a **complete style snapshot** plus
widget-specific texture slots. They serve as a **single point of definition**
for the appearance of a widget type, can be extended arbitrarily, and
allow multiple visual variants in the same frame without a push/pop stack.

#### Types

| Type | Factory | For Widgets |
|------|---------|-------------|
| `ui_slider_style` | `ui.slider_style_new()` | `slider`, `slider_int`, `drag_f32` |
| `ui_button_style` | `ui.button_style_new()` | `button`, `checkbox`, `toggle`, `radio` |
| `ui_label_style` | `ui.label_style_new()` | `label`, `label_colored`, `text_input`, `text_area` |
| `ui_progress_style` | `ui.progress_style_new()` | `progress_bar`, `progress_bar_colored` |
| `ui_panel_style` | `ui.panel_style_new()` | `rect_rounded` |

All preset types are opaque heap handles (`i8*`).

#### Creation

`ui.XXX_style_new()` **copies the current style stack top** as `base`
and initializes all texture slots with `null`. This way the preset
automatically inherits the global theme and can be selectively overridden.

```aiml
- call: [ui.push_style, theme]          # set global theme
- decl: [sl, ui_slider_style, { call: [ui.slider_style_new] }]
- call: [sl.set_thumb, thumb_tex]       # thumb sprite
- call: [sl.set_track, track_tex]       # track sprite
- call: [sl.set_hover_color, -1]        # override base.hover_color
- call: [sl.set_padding_x, 0.04]        # 4% outer gap
```

#### Common Setters (all preset types)

| Method | Type | Description |
|--------|------|-------------|
| `set_color(i32)` | — | `base.color` |
| `set_bg_color(i32)` | — | `base.bg_color` |
| `set_hover_color(i32)` | — | `base.hover_color` |
| `set_active_color(i32)` | — | `base.active_color` |
| `set_border_color(i32)` | — | `base.border_color` |
| `set_corner_radius(f32)` | — | `base.corner_radius` |
| `set_border_width(f32)` | — | `base.border_width` |
| `set_font(ui_font)` | — | `base.font` |
| `set_padding_x(f32)` | — | `base.padding_x` — horizontal outer gap |
| `set_padding_y(f32)` | — | `base.padding_y` — vertical outer gap |
| `set_size_w(f32)` | — | `base.size_w` — absolute width (-1 = auto) |
| `set_size_h(f32)` | — | `base.size_h` — absolute height (-1 = auto) |

#### Widget-Specific Setters

**`ui_slider_style`**

| Method | Description |
|--------|-------------|
| `set_thumb(gl_texture)` | Sprite for the thumb (handle); aspect ratio is preserved |
| `set_track(gl_texture)` | Sprite for the track bar |

**`ui_button_style`**

| Method | Description |
|--------|-------------|
| `set_bg(gl_texture)` | Background texture in normal state |

| Method | Description |
|--------|-------------|
| `set_fill(gl_texture)` | Texture for the filled portion of the bar |

| Method | Description |

#### Complete Example

```aiml
# ── One-time initialization ───────────────────────────────────────────────

- decl: [thumb_tex, gl_texture, { call: [gl.load_texture, "assets/slider_thumb.png"] }]
- decl: [track_tex, gl_texture, { call: [gl.load_texture, "assets/slider_track.png"] }]

- decl: [sl_style, ui_slider_style, { call: [ui.slider_style_new] }]
- call: [sl_style.set_thumb,     thumb_tex]
- call: [sl_style.set_track,     track_tex]
- call: [sl_style.set_padding_x, 0.03]   # 3% outer gap
- call: [sl_style.set_size_h,    40.0]   # fixed height 40 logical pixels

- decl: [btn_style, ui_button_style, { call: [ui.button_style_new] }]
- call: [btn_style.set_corner_radius, 8.0]
- call: [btn_style.set_bg_color,  -1593835777]   # 0xA05050FF
- call: [btn_style.set_padding_x, 0.05]

# ── In the render loop ────────────────────────────────────────────────────

- set: [vol, { call: [ui.slider, "volume", vol, 0.0, 1.0, sl_style] }]
- decl: [ok, i32, { call: [ui.button, "Confirm", btn_style] }]
```

## 6. Font System

| Call | Return | Description |
|------|--------|-------------|
| `ui.load_font(p: path, size: f32)` | `ui_font` | Load TTF font; bake atlas at `size` logical pixels |
| `ui.load_font_default(size: f32)` | `ui_font` | Load embedded default font (Proggy Clean) |
| `ui.set_default_font(font: ui_font)` | — | Default font for all subsequent widgets |

Fonts are baked as a bitmap atlas onto a GPU texture (stb_truetype).
Multiple sizes of the same font = multiple atlas textures.

## 7. Input Integration

The UI automatically consumes events from the `input` queue.
Widget IDs (FNV1a hash of the `id` string) prevent state conflicts.

| Event | Handling |
|-------|----------|
| `mouse_move` | Update hover state of all widgets |
| `mouse_button_down` | Hit test → set active widget |
| `mouse_button_up` | Trigger click result for `ui.button` |
| `text` | Write into focused `ui.text_input` / `ui.text_area` |
| `key_down "Backspace"` | Delete in focused text field |
| `key_down "Tab"` | Pass focus to next widget |

`ui.end()` consumes processed events from the queue.
Clicks into empty space remain in the queue (usable for game logic).

## 10. Implementation Notes

### 10.1 Logical Pixels

All sizes in style properties and `spacer`/`image_sized` are **logical pixels**,
automatically scaled with `engine.dpi()`:

```
physical_pixels = logical_pixels × engine.dpi()
```

Grid sizes (`buffer<f32>`) are dimensionlessly normalized — they never
directly reference pixels.

### 10.2 Layout Computation in `ui.end()`

1. Root rect = window size in physical pixels
2. Per grid: sum fixed shares (`< 1.0`) and subtract from total width/height
3. Distribute remaining space equally among all `1.0` entries
4. Subtract gap: `cell_size -= gap × (count - 1) / count`
5. `begin_cell_span`: cell rect = union of `colspan × rowspan` individual rects minus inner gaps
6. Nested grid: cell rect becomes new root rect

### 10.3 Batch Renderer

A vertex buffer (position xy, UV, RGBA color) is filled per `ui.end()`.
Texture changes (font atlas ↔ image texture) create sub-batches —
one draw call per texture group.
Rounded rectangles are rendered as quads + SDF shader trick
(no tessellation of corners needed).

### 10.4 stb_truetype

```cpp
// In ui_runtime.cpp (once):
#define STB_TRUETYPE_IMPLEMENTATION
#include "../vendor/stb_truetype.h"
```

Font atlas is uploaded as a `GL_ALPHA` texture.
Text quads blend with `color × texture.a` — arbitrary text color without
regenerating the atlas.

### 10.5 Widget State

```cpp
struct WidgetState { bool hovered; bool active; bool focused; };
unordered_map<uint32_t, WidgetState> widget_states;  // Key = FNV1a(id)
```

State is retained between frames. At frame end, states of widgets
that were not called in this frame are automatically removed.

## Offen: colour runs and a gutter for `text_area`

Requested by cosmos `doc/spec/98` (F98-2/F98-3) for a pipeline source editor.  `ui.text_area`
already carries the hard half of an editor — caret, selection, UTF-8 boundaries, clipboard, all on
**byte offsets**.  What it cannot do is show a line-number column or colour parts of its content,
so a code editor built on it today would have to be rebuilt from `ui.label_colored` plus its own
input handling, duplicating exactly the parts that are already correct.

Needed:

- an optional line-number gutter, and
- **colour runs**: a list of `(byte_start, byte_len, color)` applied while drawing.

Byte ranges, not character or column indices — the widget already uses byte offsets for caret and
selection, and a second counting scheme in the same widget would be wrong at every multi-byte
character.  Alternatively a separate `ui.code_area` sharing the same input path.
